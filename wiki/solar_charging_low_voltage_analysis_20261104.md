# 태양광 충전 중 저전압 반복 분석 — 2026-11-04

> 이 분석의 코드 기준은 당시0.2.2다. 이후 승인된0.2.3 후보의11.0V 이하 변경은 [후속 문서](low_voltage_threshold_20261104.md)를 따른다.

## 결론과 증거 범위

배터리/전원 경로의 부하 전압 강하와, 저전압 때 뚜껑을 여는 기존 정책의 설치 조건 충돌을 구분해야 한다. 닫혀야 충전된다는 소유자 설명을 설치 조건으로 사용한다. 실제 충전 전류나 오늘의 뚜껑 위치는 독립 측정하지 않았다.

2026-11-04 새 운영 데이터 조회는 실패했다. 브라우저 도구는 Work settings의 Local browser use disabled를 반환했고, 기존 signed-maintenance status는 SSH 후 sudo: a password is required / return1을 반환했다. 다른 권한으로 우회하지 않았다. 아래 수치는 [2026-11-03 실제 동작 기록](field_power_operation_20261103.md)이며 오늘 측정으로 재표시하지 않는다.

## 확정된 이전 측정

| 단계 | 전압 | 모터 분기 전류 | 결과 |
|---|---|---|---|
| 충전용 닫기 승인 | 11.90802 V | 0.4 mA | code1 / RUNNING |
| 부하 중 측정 | 11.211 V | 1368.9 mA | code3 / LOW_VOLTAGE_STOP |
| 정지 후 | 약 11.94 V | 약 0.4 mA | 보호 유지 |
| 이후 일반 열기 요청 | 약 11.94 V | 0.2–0.5 mA | actuation0, 열림 전이 미관측 |

측정 전압은 약0.70V 하락했고 설정11.3V 아래에서 닫기가 멈췄다. INA219는 당시 valid/fault0/profile0x399f/cal4096이었다. 이 증거는 무조건 센서 오류라는 설명을 지지하지 않는다. 배터리 충전 부족/열화와 배선·접점 손실, 기계 부하를 한 측정 지점으로 구분하지 못한다. 전체 장치·태양광 전류/SOC는 측정하지 않는다.

## 현재 코드에서 확인한 서로 다른 세 경로

1. 일반 동작 저전압: [BatteryPolicy](../src/BatteryPolicy.cpp)는 유효 전압이 cutoff11.3V 아래에서 연속3초면 보호를 latch한다. [servicePower](../src/SmartBoxController.cpp)는 일반 FSM에서 이 보호로 진입하면 기존 fail-open stroke를 한 번 시작한다. 설정 actuatorTime 경과 후 격리한다. 이미 보호 상태에 계속 머무르는 동안 매 loop마다 다시 여는 것은 아니다.
2. 충전용 닫기: 명시 요청/보호 상태/유효 측정/전압 기준을 확인하고 부팅당1회만 허용한다. 동작 중11.3V 미만이면 즉시 중단한다. 성공적 시간 만료와 실패 모두 stopChargingClose에서 보호를 다시 latch한다. 따라서 닫기 후 LOW BATTERY 표시는 보호의 유지일 수 있으며 새로운 저전압 이벤트를 뜻하지 않는다. 이 경로는 종료 후 자동으로 다시 열지 않는다.
3. 보호 복구: max(12.0V, cutoff+0.7V) 이상이 연속300초여야 latch가 풀린다. 한 번의 전압 하락, 무효 측정 또는2초 초과 측정 공백은 연속 시간을 초기화한다. 복구 tick은 릴레이 격리 후 IDLE로만 가며 즉시 자동 열기를 수행하지 않는다. 다음 loop부터는 정상 센서/사용자 동작이 다시 허용된다.

일반 force_open/force_close는 보호 상태에서 허용되지 않는다. 이전 부팅의 충전용 닫기1회는 이미 소모됐지만 오늘 재부팅 여부는 확인하지 못했다. 재부팅으로 제한을 초기화하지 않는다.

## 현장 조건과 충돌하는 구조

소유자 조건이 닫힘→충전 가능이면, 일반 동작 저전압→강제 열림→충전 곤란이라는 경로가 생긴다. 또한 충전 중 무부하12.0V/5분만으로 모터 전체 stroke의 공급 능력은 증명되지 않는다. 복구 뒤 다음 동작에서 전압 강하가 재현되면 다시 보호/fail-open으로 갈 수 있다. 이는 오늘 실제 전이가 확인됐다는 뜻이 아니라 코드와 이전 부하 기록으로 확인한 가능한 실패 경로다.

0.2.2는 명시적 충전용 닫기를 추가하고 복구12.4→12.0V로 낮췄지만 기존 일반 저전압 fail-open 정책을 유지했다. 그러므로 설치 조건에 대한 이 충돌을 아직 해결하지 못했다.

## 개선 우선순위 — 제안이며 미적용

- P0: 저전압 보호에서 자동 열기 대신 릴레이 격리/현재 위치 유지 정책을 검토한다. 충전용 닫기 요청과 일반 저전압 진입을 하나의 명시적 충전 대기 정책으로 정리한다. 임의 자동 닫기나 센서/과전류/방향 interlock 우회는 제안하지 않는다.
- P1: 충전 대기 중 자동 감지를 언제 재개할지 명시하고, 안정 전압과 실제 부하 성공을 별도 증거로 관리한다. 기준 전압만 더 낮추는 것으로 모터 전력 부족이 해결된다고 주장하지 않는다.
- P1: 명령별 수락/거절 사유, 차단 전후 전압·전류·최저 전압, 복구 count/남은 시간, 측정 유효성을 이벤트로 수집한다. 보호 유지/새 차단/RECOVERING/명령 거절을 UI에서 구분한다.
- P2: 배터리 단자와 모터 입력 전압의 동시 측정 및 충전 컨트롤러/충전 전류 증거로 전원·배선·기계 부하를 분리한다. 원격 측정 범위가 부족하면 원인을 하나로 단정하지 않는다.

오늘 사건을 확정하려면 동작 직전/직후의 새 non-retained telemetry와 fsm/power state, recovery_count, close_state/used, driver/fault, command 결과가 필요하다. 과거 retained packet이나 수신 시각만으로 오늘 사건을 구성하지 않는다.
