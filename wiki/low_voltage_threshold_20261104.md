# 11.0 V 보호 기준 변경 — 2026-11-04

## 승인 범위

소유자가 오늘도 같은 현상이 발생했다고 확인하고 보호를11V 이하로 변경하도록 명시했다. 정확히11.0V를 포함한다. source0.2.3 후보는 기본 보호 진입11.3V 미만→11.0V 이하, 일반3초 연속 조건을 적용한다. 일반 모터 시작은11.0V 초과가 필요하고 명시 충전용 닫기는11.0V 이하에서 즉시 중단한다.

복구12.0V/300초, 강제OTA max(11.7V, cutoff+0.4V)/30초, 센서 유효성·과전류·접점 interlock·최대 동작 시간·요청TTL·부팅당 시도 제한은 유지한다. 기존 일반 저전압 fail-open 정책 변경은 이번 요청에 포함하지 않았다.

## 이전 현상에 대한 의미

11월3일 실제 부하 측정11.211V는 새 기준보다 높다. 새 기준의 실제 Controller 모의 시험에서는 이 전압에서 충전용 닫기가 계속되고11.0V에서 멈춘다. 이는 실제 stroke 완료/현장 충분한 전력/충전 성공을 보증하지 않는다. 오늘 현상은 소유자 보고이며 아직 새 운영 telemetry를 확보하지 못했다.

이미 latch된 보호는 단순히11.0V를 초과했다는 이유로 해제하지 않는다. 기존12.0V/5분 안정 조건이 필요하다. 따라서 기준 변경은 보호 재진입 및 닫기 중단 기준의 변경이지 보호 해제 명령이 아니다.

## 저장된 설정의 전환

[ConfigManager](../src/ConfigManager.cpp)는 설치 장치의 이전 기본 volt_lim11.3V를11.0V로 읽어 적용하고 이 key만 저장한다. 정상 전환 뒤 다음 부팅에서 다시 쓰지 않는다. 사용자 별도값은 보존하며 비정상 NaN/범위 값은 새 기본값으로 복구한다. 쓰기 실패 시 경고를 남기고 현재 runtime은 새 값으로 유지하며 다음 부팅에 재시도한다. 다른 모터/OTA/네트워크/lid 설정 전체를 다시 저장하지 않는다.

새 기본값은 [BatteryPolicy](../src/BatteryPolicy.h)에 중앙화했다. 일반 구동/충전 닫기/알려진 저전압에서의 sensor-fault OTA 경계도11.0V 이하를 일치시킨다. 경고/절전 수준은 기존 cutoff 상대 offset을 따르며 자동 복구 floor12.0V는 유지한다.

## 운영 OTA 게시 — 설치와 별도

소유자가 OTA 경로 사용을 재요청했다. 관리자SSH sudo 실패가 OTA 게시 불가를 의미하지는 않는다. 기존CI의 별도SFTP 배포 계정으로 게시할 수 있음을 실제로 확인했다.

PR22는 최종head37a7c53의 CI41772499489 성공 후 ready로 전환했다. 일반 병합은 기존 main update 제한에 걸렸으며, 실제 ruleset은 OrganizationAdmin always/current_user_can_bypass always를 지정한다. 기존 허용 관리자 경로로 squash 병합했고, ruleset·권한·계정 설정은 변경하지 않았다. 병합main1c093943108a04fdc01d13cc7eb5fed038f98f89의 자동 게시41773087153는 시험·익명 차단 검사·운영C6 build·SFTP 배포 모두 PASS다.

게시version0.2.3-g1c09394 /1418992B /SHA256d0e788cbf94f525d7534a25dfc9e98897a79957c8606dcf19a7907853c897011. 기존 비공개nativeUSB 후보0.2.3-g4f3d7b3와 운영UART build는 서로 다른 이미지이므로 해시·버전을 섞지 않는다.

읽기 전용 검증41773546122도 PASS: 올바른 인증 HEAD/GET4개200, 익명·잘못된 인증 거절8개, TLS hostname/chain 검증, 실제 다운로드버전/크기/해시가 게시metadata와 일치했다. 실제 firmware/version.json이 OTA 경로에 게시된 것은 수용한다.

장치의 명시 force_ota/trigger_ota는 아직 전송하지 않았다. 브라우저 기능이 Work settings에서 비활성화돼 기존HA 세션으로 최신 전원 상태/실제설치 버전을 읽지 못한다. 소유자에게 로컬 브라우저 사용과 HA 로그인 접근을 요청했다. 자동OTA가 설치했는지 추정하지 않으며, 설치·새부팅·11V migration 수용은 미확인이다. 서버root 접속 복구를 OTA의 필수 조건으로 다시 요구하지 않는다.
