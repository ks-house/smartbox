# 2026-11-04 열기 기동 범위 오류

## 현장 증거

운영0.2.5-g945e031에서 사용자17:59:14 강제 열기는 OPEN_START → OPENING/SENSOR_RECHECK17:59:15 → IDLE17:59:17이었다. 사용자는 기존 CCTV에서 처음부터 움직이지 않았다고 확인했다. Influx17:59:16.242 수신은 fault9/RANGE, mask6, config0x399f/cal4096, raw bus10.084V/shunt320mV/current3200mA였고17:59:17.259에는 유효12.26405V/0.2mA로 회복했다. persistent_hold는0이었다.

18:25:41 수동 열기도 동일했다.18:32:08 초음파 감지 후18:32:09 자동 OPEN_START/OPENING/SENSOR_RECHECK →18:32:11 IDLE도 확인했다. 이후 진단은 마지막 fault9/mask6/raw10.128V/320mV/3200mA와 정상 대기12.24004V/0.5mA였다. 자동 감지는 도달하며 공통 측정/차단 단계에서 중단된다. IDLE은 실제 개방 성공이 아니다.

SENSOR_RECHECK는0.2.5에 추가되어 오늘17:24 설치부터 사용됐다. 범위 검증 소스 자체는10월31일f7a869c부터, 연속 읽기는11월1일363a5f7부터다. 소스 도입과 현장 설치를 구분한다.

## 확인된 충돌과 한계

모터 FSM의 기존500ms 기동 전류 유예보다 servicePower의 범위 오류 정지가 먼저 실행된다. [TI INA219 데이터시트](https://www.ti.com/lit/ds/symlink/ina219.pdf)의320mV 포화 값은 정확한 실제 최대 전류가 아니다. 저장된5A stall 설정은 현재0.1ohm 가정의3.2A 측정 상한을 넘는다. raw bus는 VIN-minus 측정이므로 배터리 단자 전압으로 단정하지 않는다.

정상 기동 과도 전류/기구 걸림/끝단/방향/배선/전원 부족은 미분리 상태다. 정확한 액추에이터 기동·스톨 정격과 실제 모듈 shunt 표시는 미확인이다. 센서 범위나 stall 설정은 이번에 확대하지 않는다.

##0.2.6 후보

사용자 요청대로 기동 중 불필요한 SENSOR_RECHECK 진입을 줄이되, 전체 센서 오류 정지는 제거하지 않는다.

- 이미 출력이 인가된 일반 OPENING 최초500ms 미만만 적용한다. driver1/config399f/cal4096/RANGE/mask6/유한0~16V bus/양의320mV·3200mA 조합만 보류한다. 닫기·보호 닫기·대기·OTA에는 적용하지 않는다.
- 포화 표본은 invalid로 유지하고 raw/마지막 오류를 보존한다. 이전 유효 전압의 시각을 갱신하지 않으며 대외 valid/admission/OTA-ready는 false다. 배터리·경고·OTA의 연속 정상 시간도 초기화하여 이 구간을 누적하지 않는다.
-500ms에는200ms 주기와 무관하게 재측정한다. 계속 포화/센서 오류면 즉시 격리/SENSOR_RECHECK. 정상으로 돌아오면 진행한다. 반복 forceOpen은 열기 중 무시하여 시간을 연장하지 않는다.
- I2C/profile/calibration/비수치/다른 범위 오류는 즉시 정지한다. 릴레이 인터록, 스트로크 제한, OTA 격리,11V/3초 보호와11V/300초 경고는 유지한다.

최초500ms는 실제 전류가 센서 상한을 얼마나 넘는지 판정할 수 없다. 하드웨어 원인 해결이나 실제 개방 성공을 뜻하지 않는다. 게시·설치·물리 결과는 별도 수용한다.

## 검증

기동 범위/수동/초음파/반복 요청/500ms 경계4건이 기존 코드에서 실패한 뒤 수정으로 통과했다. 리뷰에서 invalid 구간이 OTA 정상 시간에 누적되는 문제가 발견되어 실제 controller 재현을 RED 확인하고 연속 자격 시간을 끊도록 수정했다. 추가 정상 오류·닫기 거절 경우를 포함한다. 최종 빌드·CI·설치 결과는 로그와 후속 수용 항목을 따른다.
