# SmartBox private OTA publishing

The proposed route is GitHub Actions → Tailscale → NAS SFTP. The device still uses its existing authenticated HTTPS manifest and firmware URLs. This changes no device controls, OTA admission rules, router settings, NAS firewall, management SSH, or Gatekeeper configuration.

## Provision before enabling production

1. Set up the GitHub environment `smartbox-private-ota`, restricted to the protected `main` branch. Use a dedicated short-lived Tailscale federated identity for this exact repository/environment, restricted to `main`, with only auth-key capability and tag `tag:smartbox-github-ota`. Permit only the NAS SFTP destination/port; do not reuse the Gatekeeper identity, grant a shell, widen NAS permissions, or use an always-on key.
2. In that environment configure `SMARTBOX_TS_OIDC_CLIENT_ID`, `SMARTBOX_TS_OIDC_AUDIENCE`, `SMARTBOX_SFTP_HOST` (literal Tailscale IPv4), `SMARTBOX_SFTP_PORT`, `SMARTBOX_SFTP_STAGE_DIR`, and `SMARTBOX_SFTP_HOST_KEY` (two fields, `ssh-ed25519 <public-key-blob>`, verified against the NAS through an already trusted management path). Never discover and trust a new key over the public route. Use the existing scoped publisher identity and destination through `NAS_USER`, `NAS_PASSWORD`, and `NAS_TARGET_DIR`; keep values in Secrets. Do not export or paste them into chat.
3. Staging must be outside every HTTP document root or alias and on the same filesystem as the final destination. The SFTP account needs only staging and existing OTA publication access. Check the real layout and overwrite-by-rename support administratively. The publisher rejects overlapping configured paths, but this does not prove the NAS layout or permissions. Save the currently served image and manifest in the approved non-web rollback location before the live run.
4. Dispatch `verify-private-sftp` on reviewed `main`. It only authenticates and changes the session's working directory to each configured location. It does not show write access, perform an upload, or run a firmware build. The public SFTP path is not used. The current protected HTTPS denial gate must still pass.
5. After preflight and rollback readiness, set the repository Actions variable `SMARTBOX_OTA_PUBLISH_ENABLED=true`; then dispatch `publish-firmware` on the reviewed main commit. That variable also enables the existing main-push publication trigger. No credentials or binary are retained as Actions artifacts. Both files are staged before the firmware and then manifest are promoted. These are two renames, not an atomic pair. If interruption or failure leaves a mismatched pair, stop and use the approved rollback; do not trigger OTA on a mismatched pair.
6. Require authenticated HTTPS readback of the exact version and firmware SHA-256, with anonymous and wrong-password access denied. Use normal device OTA only with fresh idle/voltage-ready telemetry. Record the installed version and a new healthy boot. Publication alone is not installation. Closing any public NAS port is a separate task.

No live private SFTP preflight, production publication or device installation is established by this document.
