# SmartBox offline field recovery kit

Owner request: prepare equipment, corrected firmware and field instructions for a visit; no remote installation or motor operation now.

Use the already-reviewed0.2.1 correction in PR22. USB bypasses the running application's OTA admission; firmware remains uninstalled and the operating manifest remains held. Build real provisioned firmware only in the existing trusted Actions secret context; encrypt a private bundle to a one-use owner-held CMS/AES256-GCM recipient before uploading any artifact. No plain credential-bearing image/header in Git, Actions artifacts, console or wiki. Decrypt only to a new owner-private Windows field-kit directory.

Approach: Windows USB/esptool portable tool, WSL source/build/validation. Default tool behavior is offline verify/plan. Apply requires the operator physically disconnecting actuator power and board external5V (USB only). Read chip/security/flash first; reject other chips, less/different than16MB, encryption/secure boot or unknown layout. Preserve bootloader/partition table/NVS and the second OTA slot. Snapshot all sectors about to be overwritten plus original otadata and NVS; write only app0 at0x10000 and reviewed boot_app0 selection data at0xe000, verify and prove NVS unchanged, leave the board in ROM download mode for controlled commissioning. No erase-all/factory full-image default. Provide exact restore of overwritten app span and prior otadata, bound to the same device/MAC and snapshot hashes.

Equipment: existing Windows laptop, two data USB cables, multimeter, insulated screwdrivers/labels/prop, spare matching INA219 and jumpers; spare MCU only verified ESP32-C6/16MB (official common DevKitC-1 N8 is8MB). Driver package and official links for USB-UART; nativeUSB fallback. Observe3.3V GPIO/I2C pullups; isolate buck5V before USB. For powered sensor measurement only, battery Vin+ may be restored with motor power physically disconnected and external board5V disconnected. Do not diagnose0V at a deliberately unpowered INA219 Vin+ as a firmware fault. Do not disturb solar-controller battery/PV wiring for USB recovery.

Success: ready local private artifact with source commit/version/hash/chip/partition metadata, authentic portable flasher, guarded scripts verified without a physical device, equipment list, Korean field checklist/diagnostic branches and acceptance sheet. Physical USB/measurement/motion/charging acceptance stays pending.

Field image uses env:esp32-c6-field-recovery, native USB Serial/JTAG CDC on GPIO12/13 (not used by controller) and zero TX wait; no wait-for-host loop. Standard runtime publisher retains its UART profile. Third-party CP210x download is unavailable in this environment, so the field-native USB image is the primary log/flash path; native USB enumeration is still a field Gate.

Reviewed retry contract: one script-level write invocation; pinned official esptool5.3.0 may perform bounded vendor internal write/reconnect retry. Operator must keep the same physically isolated board and cable connected until the process exits. On errors do not assume download mode or successful verification; keep motors disconnected. Fixed verified ESPTOOL_CFGFILE excludes user custom reset sequences. Backup files are flushed to disk and metadata write-through precedes any write. Actual boot version is unconfirmed after both flash and restore.
