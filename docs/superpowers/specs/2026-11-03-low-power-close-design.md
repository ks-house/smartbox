# 저전압 보호 중 충전을 위한 닫기 전용 복구

상태: 2026-11-03 사용자 설계 승인 및 추가 보호 해제 기준 인하 요청 반영. 사용자 선택: 닫기 전용 복구. 추가 요청: 강제 OTA. 아직 구현/현장 설치/닫기 명령 전송 없음.

## 목적과 선택

소유자가 현장 뚜껑 열림 때문에 태양광 충전이 안 된다고 보고하고 닫기를 요청했다. 기존 force_close는 power.actuationAllowed와 BATTERY_LOW_SHUTDOWN 차단 조건 때문에 보호 중 거절된다. 전체 보호 ON/OFF는 자동 열림과 다른 구동까지 재허용하므로 선택하지 않았다. 보호 래치를 유지하는 사용자 명시 닫기 1회 경로를 추가한다.

## 동작 계약

- 인증된 기존 MQTT 제어 경로에 별도 close_for_charging 명령과 Home Assistant 버튼을 추가한다. 일반 force_close와 force_open의 기존 권한/보호 조건은 유지한다.
- 보호 상태, 모터 정지, OTA/비상 정지 아님, 신선하고 유효한 전압·전류를 모두 확인한다. 시작 전 즉시 다시 측정하고 전압이 기존 voltageShutdownLimit(기본 11.3V) 이상이며 16V 이하인 경우에만 허용한다. 이 기준은 12.0V/300초 일반 보호 해제와 다르다. 차단 기준 미만/무효/오래된 자료는 거절한다.
- 한 요청은 닫기 방향 1회만 실행한다. retained/duplicate 요청을 거절하고, 유효한 요청 ID와 짧은 유효기간 및 재사용 차단으로 지연 실행/중복 구동을 막는다. 자동 재시도·자동 개방은 하지 않는다.
- Main OFF → 100ms 접점 분리 → close 방향 → 100ms 안정화 → Main ON 순서를 유지한다. 구동 시간은 설정 actuatorTime과 절대 3800ms 중 짧은 값으로 제한한다. 기존 전류 크기 판정/초기 돌입 보호를 유지하고 과전류·차단 전압 미만·센서 오류 시 출력 격리 후 종료한다.
- 구동 종료 후 모든 릴레이를 격리하고 저전압 보호를 유지한다. 보호 중 새 사람 감지/일반 열기/정비 열림은 허용하지 않는다. 종료·중단은 구분해 보고하며 리미트 센서가 없어 시간 종료를 실제 닫힘 완료라고 표현하지 않는다.
- 최소 max(12.0V,cutoff+0.7V)가 신선한 측정으로 300초 연속 유지되어야 일반 보호를 해제한다. 해제 순간 구동하지 않고 이후 새 사람 감지부터 정상 자동 열기를 재개한다. 전압 하락/측정 공백은 기존 회복 판정을 다시 시작한다.
- 별도 소모성 닫기 상태와 결과/거절 사유를 텔레메트리에 내보낸다. 완료 후 다시 보내진 동일 요청은 거절하며, 장애 후 자동 반복/부팅 시 반복 구동은 없다.

## 구현·검증 범위

실제 Controller와 MQTT 요청 검증의 host 회귀로 보호12.0V 닫기 1회, 회복 전 자동 열기 차단, 12.0V/300초 뒤 감지 재개, 저전압/과전류/NaN/오래된 측정 중단, 최대시간, 접점 순서, replay/retained/expiry, OTA 비회귀를 검증한다. 기존 Python/native suite와 UART/nativeUSB C6 빌드를 확인하고 독립 코드 리뷰를 받는다. 모터 물리 완료는 현장 증거가 필요하다.

## 현재 설치 한계

실제 USB 부팅으로 확인된 0.2.1-g4a57756에는 close_for_charging이 없다. 정상 OTA는 IDLE와 보호 해제/충전 전압을 요구하고 recovery OTA는 SENSOR_FAULT만 허용하므로 유효한 저전압 보호를 원격 설정으로 해제할 수 없다. 수정 펌웨어를 빌드해도 즉시 원격 설치했다고 보고하지 않는다. USB 설치 또는 정상 설치 조건 확보가 필요할 수 있다. 운영 manifest hold를 자동 해제하지 않는다.

2026-11-03 재확인: signed maintenance status는 SSH 인증 후 sudo password-required로 실패한다. 브라우저 제어는 Work settings에서 비활성화되어 최신 Grafana 수치를 재조회하지 못했다. 전일 12.00V는 현재 전압으로 재사용하지 않는다. 비밀번호/권한 우회나 임의 reboot/OTA/motor publish 없음.

## 추가 요청: 명시적 강제 OTA

- 별도 force_ota 요청으로 자동 일정·일반 보호 해제 5분 대기·동일 버전 생략 조건을 우회하는 사용자 유지보수 경로를 제공한다. 기존 자동/일반 trigger_ota 계약은 유지한다.
- 모터 정지/출력 완전 격리/OTA 중복 없음/신선한 실제 전압·전류 확인이 필수다. 기본 제안은 기존 saving 경계 cutoff+0.4V(기본11.7V) 이상을30초 연속 유지하고 알려진 과전압16V 초과·센서 오류를 거절하는 것이다. 이 값은 에이전트가 제안한 소프트웨어 입장 조건이며 배터리 SOC·MCU 전원 안정성을 보증하지 않는다. 센서 불명 상태는 기존 별도 sensor-fault recovery 계약으로 유지하며 새 경로에서 거짓 정상으로 만들지 않는다.
- 요청 ID/최대120초 TTL/retained·duplicate·replay 거절, 부팅당 1회만 플래시 예약한다. 대기 요청도 원래 TTL 만료 뒤 실행하지 않는다. manifest hold404·인증/TLS 실패는 강제로 무시하지 않는다.
- 이미지 비교보다 먼저 원자적으로 출력 격리 상태를 예약하며 정상/닫기 구동과 상호 배제한다. 플래시 직전에 전압과 원래 TTL을 다시 검사한다. 현재 httpUpdate.update는 동기 플래시이므로 진행 중 즉시 안전 중단을 이미 제공한다고 주장하지 않는다. 구현 시 실제 updater의 중단/비활성 슬롯 및 commit 경계를 검증하며 기존 bootable slot을 유지한다.
- 실패/동일 이미지 유지보수 종료 뒤 보호 래치를 보존한다. 성공은 다운로드/PUBACK가 아니라 설치→재부팅→버전·부팅 건강 확인까지 관찰하며 실제 뚜껑 닫힘과 구분한다.
- 현재 설치된0.2.1의 유효 저전압 OTA 제한을 소급 변경하지 못한다. 새 기능은 최초 USB 설치 또는 기존 조건을 충족한 OTA 뒤부터 사용 가능하다.

추가 지시 반영: 기본 보호 해제 기준12.4→12.0V로 인하하되300초 연속 조건과 기존 구동 차단11.3V는 유지한다. 사용자가 승인한 닫기·강제OTA 설계에 대한 변경이며 아직 배포 사실은 아니다.
